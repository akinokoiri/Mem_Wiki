# 芒伊木 Wiki - 基础布局修复设计方案

## 1. 目标与背景
**目标**：修复当前 VitePress 页面中，正文的横向元素（如 `<hr>` 分割线、`h1`/`h2` 标题的底部边框）会穿透或连接到右侧悬浮卡片（`Infobox`, `MediaCard`）的视觉 Bug。
**背景**：基于用户对 `WX-78 Wiki` 成功案例的考察，我们决定放弃 VitePress 的现代居中博客流排版，转向传统的**浮动避让（Float Logic）** Wiki 风格。即块级元素在遇到右侧浮动的卡片时，应自动缩短宽度，实现视觉上的“零件不相连”。

## 2. 架构与实现逻辑
本次修复纯粹在 CSS 层面进行调整，不修改任何 Vue 组件的 DOM 结构。

### 2.1 右侧卡片 (浮动源)
- 组件：`.infobox`, `.media-card`
- 规则：
  - 维持 `float: right;`。
  - 添加 `clear: right;` 确保多个卡片在右侧垂直堆叠，不发生水平碰撞。
  - 设置 `margin-left: 24px;` 及 `margin-bottom: 24px;` 确保与左侧被避让的内容之间有明确的呼吸空间（即截图中强调的“大片空白”概念，用于视觉隔离）。

### 2.2 正文内容区 (避让目标)
- 元素：`.vp-doc h1`, `.vp-doc h2`, `.vp-doc h3`, `.vp-doc hr`, `.vp-doc p`, `.vp-doc blockquote`
- 规则：
  - **移除强制清理**：确保 `.vp-doc hr` 等元素**没有**使用 `clear: both`，否则它们会强制跳到浮动卡片的下方，破坏版面。
  - **触发 BFC (Block Formatting Context)**：对于带有底部边框的标题（`h2`等），通过设置 `overflow: hidden;` 或调整 `display` 属性触发 BFC，使其宽度被右侧的浮动元素强制限制，从而实现边框自动截断，不穿透卡片。

### 2.3 布局宽度 (保留选项A基调)
- 继续维持前一阶段设定的较宽内容区（`1100px`），确保文字整体偏左，右侧为卡片保留足够的浮动通道。

## 3. 测试与验证标准
1. **分割线截断测试**：在插入了 `<MediaCard>` 的段落上下插入 `---`（`<hr>`）。分割线应该只在文字区域内显示，其右侧终点应停在距离卡片左侧外边距（24px）的位置，绝不触碰卡片边框。
2. **标题边框测试**：在浮动卡片旁边放置带有底部边框的 `## 标题`。底部边框同样应该被卡片截断。
3. **多卡片测试**：连续放置两个浮动卡片，它们应在右侧垂直排列，不重叠。

## 4. 后续规划 (非本次范围)
