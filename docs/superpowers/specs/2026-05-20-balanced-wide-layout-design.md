# 芒伊木 Wiki - 平衡宽幅布局设计方案 (Balanced Wide Wiki)

## 1. 目标与背景
**目标**：消除正文与右侧大纲（Aside）之间不自然的巨大空白，通过重新分配空间比例，使页面视觉平衡，消除右侧大纲的“孤岛感/小广告感”。
**背景**：之前的修改虽然解决了重叠问题并撑开了布局，但由于正文最大宽度限制较死，导致在高分辨率屏幕下，正文与大纲之间留下了无法利用的空隙。用户希望两者能够更自然地平分或平衡展示空间。

## 2. 架构与布局逻辑
放弃硬性的像素宽度对齐，转向基于弹性比例的平衡布局。

### 2.1 整体容器平衡
- **容器对齐**：`.VPDoc .container` 将作为一个整体容器，承载“正文”和“大纲”。
- **对齐策略**：在桌面端使用 `justify-content: center;`，但在两个子板块之间设置合理的 `gap`（间距），确保它们既不拥挤也不疏离。

### 2.2 右侧大纲 (Aside) 强化
- **宽度增加**：将 `.aside` 和 `.aside-container` 的固定宽度从 `220px` 增加到 `300px`。
- **视觉厚度**：增加内部左侧的 `padding`（如 `48px`），使大纲内容更靠近视觉中心，同时给左侧留出足够的留白，显得更有“分量”。

### 2.3 正文区 (Content Area) 弹性调整
- **宽度上限提升**：设置 `.VPDoc .content-container` 的最大宽度为 `1200px`（包含 Infobox 浮动空间）。
- **动态填充**：在超宽屏（>1600px）下，适当增加正文与大纲之间的 `gap`，但确保这个 `gap` 不超过视觉可接受的范围（如 `80px`）。

## 3. 实现细节 (CSS)
- 移除之前版本中过度保守的 `max-width: 700px` 限制。
- 确保浮动逻辑（Float & BFC）在更宽的容器下依然有效，不产生重叠。
- 优化媒体查询断点，确保在 1280px 到 1920px 之间都有平滑的过渡。

## 4. 验证标准
1. **视觉平衡测试**：在 1080p 屏幕下，正文左侧、中间空隙、大纲右侧的比例应接近对称或有节奏的递进，无突兀的大坑。
2. **Aside 可读性测试**：大纲栏的标题和列表项有充足的横向空间，不发生局促的换行。
3. **响应式一致性**：在缩放浏览器窗口时，两个板块应同步收缩或位移，不发生突兀的跳变。

## 5. 后续规划
为未来可能加入的“多栏数据展示”提供充足的横向空间支持。
