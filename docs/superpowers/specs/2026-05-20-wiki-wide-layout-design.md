# 芒伊木 Wiki - 响应式宽幅 Wiki 布局设计方案

## 1. 目标与背景
**目标**：彻底消除 VitePress 在宽屏模式下产生的右侧巨大空白区域，提升信息展示密度。
**背景**：当前的布局虽然修复了组件冲突，但依然保留了 VitePress 默认的“现代博客”比例（正文居中，两侧留白巨大）。用户希望模仿专业 Wiki 的高密度排版，让内容撑满屏幕，并让右侧大纲紧贴正文。

## 2. 架构与布局逻辑
通过重写 VitePress 的 CSS 变量和局部容器样式，将布局中心点向右偏移，并释放正文宽度。

### 2.1 整体框架扩展
- **全局宽度**：设置 `--vp-layout-max-width` 为 `1600px`。
- **内边距优化**：在桌面端（`min-width: 960px`）下，减小 `.VPDoc` 的左右 `padding` 为 `32px`，从而让组件贴近屏幕边缘。

### 2.2 正文区 (Content Area) 深度扩容
- **容器解锁**：`.VPDoc .container` 设置 `max-width: 100% !important;`。
- **阅读宽度限制**：为了防止文字行过长导致阅读疲劳，设置正文文字容器（`.content-container`）的最大宽度为 `1200px`，但这部分空间包含了右侧浮动的卡片（Infobox）。
- **左对齐倾向**：确保正文区域在整体容器中不进行居中对齐，而是保持传统的 Wiki 左对齐风格，右侧留给浮动挂件和大纲。

### 2.3 右侧大纲 (Aside) 紧凑化
- **宽度收窄**：将原本占据较大比例的 `.aside` 宽度固定为 `220px`。
- **位置紧贴**：移除 `.aside` 容器上的 `padding-left` 和右侧可能的 `margin`，使其作为正文的紧凑附件存在。
- **在大屏幕下的行为**：当屏幕宽度足够时，Aside 应该紧贴在 1200px 宽的正文右侧，而不是飘到屏幕最右边。

## 3. 实现细节 (CSS 关键点)
- 使用 `@media (min-width: 1280px)` 和 `@media (min-width: 1440px)` 针对不同宽度的桌面端进行精细调整。
- 确保 `.VPContent.has-sidebar` 的逻辑依然稳固，不产生新的重叠。

## 4. 验证标准
1. **空白消除测试**：在 1080p 或更高分辨率的显示器上查看，右侧不应出现超过 100px 的无意义纯白区域。
2. ** Aside 对齐测试**：右侧的“本页大纲”应紧贴在正文文字/卡片的右侧，视觉上属于同一信息块。
3. **响应式回归**：确保在 768px 以下的移动端，布局依然能正确退回到单栏滚动模式。

## 5. 展望
此布局将为后续引入“高密度数据表格（WikiTable）”打下地盘基础。
