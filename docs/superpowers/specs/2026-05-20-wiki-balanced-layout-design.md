# 芒伊木 Wiki - 平衡居中 Wiki 布局设计方案

## 1. 目标与背景
**目标**：消除“右侧边栏像小广告”的廉价感，通过平衡比例和恢复整体居中，打造稳重且高密度的专业 Wiki 观感。
**背景**：之前的尝试中，为了消灭空白，我们将右侧大纲（Aside）极度压缩并强制布局左对齐，导致视觉重心偏移且 Aside 显得过于单薄。用户希望“多给右侧一点空间”，并让正文与右侧边栏平分间隙。

## 2. 架构与布局逻辑
回归“对称平衡”美学，不再追求极致的左对齐，而是通过合理的比例分配来填补空间。

### 2.1 整体容器回归居中
- **恢复居中**：移除 `justify-content: flex-start` 和 `margin: 0 !important`。让整个页面主体（Sidebar + Doc + Aside）在宽屏下重新水平居中。
- **宽度微调**：设置 `--vp-layout-max-width` 为一个稳定的值（如 `1560px`），确保在大屏幕上既不过于空旷，也不会显得拥挤。

### 2.2 右侧边栏 (Aside) 强化
- **增加分量**：将 Aside 宽度从 `220px` 增加到 `320px`。这为大纲文字提供了充足的呼吸空间，使其看起来像是一个正式的功能板块而非贴片插件。
- **内部对齐**：Aside 内部容器也同步扩展至 `320px`。

### 2.3 “一人一半”的空间消化逻辑
- **间距平衡**：
    - 正文（Content）与右侧边栏（Aside）之间保留约 `40px - 60px` 的固定 Gap。
    - 剩余的屏幕空间由页面左右两边的 Margin 平分。
- **容器宽度限制**：设置正文 `.content-container` 的 `max-width` 约为 `1000px`。这样 [1000px (正文) + 60px (间距) + 320px (Aside)] 总计约 `1380px`，在 `1560px` 的外壳中显得非常紧凑且对称。

## 3. 实现细节 (CSS 关键点)
- 清理之前过于激进的 `!important` 覆盖，利用 VitePress 默认的居中机制。
- 使用 `flex` 布局微调正文和 Aside 的占比。

## 4. 验证标准
1. **视觉平衡测试**：在大屏幕上，页面中心轴线应处于正文偏右一点的位置，整体视觉重心不再左倾。
2. ** Aside 观感测试**：右侧大纲栏应显得厚实、正式，文字不拥挤。
3. **“一人一半”测试**：正文右侧到 Aside 的距离，应与 Aside 右侧到屏幕边缘的距离在视觉上达到某种程度的呼应或平衡。

## 5. 后续规划
在拥有了稳定的 320px 右侧空间后，未来可以考虑在 Aside 区域放置更多快捷工具或统计图表。
