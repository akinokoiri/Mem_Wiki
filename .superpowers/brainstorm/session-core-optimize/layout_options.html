选择排版优化方案

针对《芒伊木》Wiki core.md 中“死亡复活惩罚”和“兽化形态”大段文字的重构方向进行决策

为什么当前看的眼睛累？

原因在于信息层级不够立体。目前的排版中，包含各种复杂的数据变化（如：复生虚弱的层数倒计时、兽化形态下的数值增益与佩戴代价），所有的文本都在同一个层级平铺展开，缺乏呼吸感与快速定位锚点。

A

方案 A：子网格双栏卡片化（强烈推荐 ⭐⭐⭐）

使用 Wiki 现有的 .item-card、.item-sub-grid 和 .sub-card 样式进行模块化重构。

重构效果：
  • 死亡复活惩罚：改造成一个大的 item-card。左侧使用 3 栏/2 栏 item-sub-grid 将 复生虚弱、灵魂震荡、灵魂裂痕 置于独立的 sub-card 卡片中，右侧放置尸体/裂痕示意图 MediaCard。
  • 兽化形态：主栏使用 item-sub-grid 将数值强化、特殊机制（跳跃/捕猎）、高级天赋强化划分为 3 个独立的 sub-card，右侧与极限攻速对比图完美并排，极具视觉冲击力。
B

方案 B：原版风手风琴折叠（折叠面板）

使用 <details> 标签将复杂细则进行折叠隐藏，只暴露最核心的结论标题。

重构效果：
  • 死亡复活惩罚：默认只显示“三项永久/动态减益”，用户点击“展开细则”后才会拉开食用各种心房的清除机制列表，主页保持极度干净。
  • 兽化形态：按“属性加成与代价”、“专属主动技能”、“相关升级技能”折叠，仅保留 3 行大标题，点击后才平滑展开。缺点是需要用户额外点击，影响直观检索效率。
C

方案 C：紧凑矩阵对比图表（数据图表化）

将长段落的判定和数值全盘转化为紧凑的无边框对比表格（类似物品/料理配方表格）。

重构效果：
  • 死亡复活惩罚：制作一个“清除/缓解复生虚弱对照表”，第一列为清除材料（告密的心、暗影心房等），第二列为效果（持续时间变短、层数变化、获得澎湃心核等）。
  • 兽化形态：把属性变化做成紧凑的两列，左侧为强化（+35% 移速、+120保暖等），右侧为限制（无法手部装备等），搭配微型图标。

视觉方案对比预览

方案 A (卡片格栅) 的优势

  • 视觉一致性高：完美继承现有 Wiki items.md 已经极度成熟且高级的 CSS 布局系统。
  • 呼吸感强：卡片外边框、内阴影和自适应双栏可以让长文字获得绝佳的“透气”空间。
  • 扫视效率高：用户一拉到底能瞬间认出“这是一个独立机制模块”。

方案 B (手风琴) / 方案 C (图表) 的不足

  • 手风琴：隐藏了过多内容，导致关键属性无法被浏览器 Ctrl+F 瞬间搜到或直观浏览。
  • 图表：纯数据表格对于有大量虚构层或复杂机制文案（如：跳跃防止落海、藏食物刨坑保鲜等细节）会显得过于僵硬，塞不下长文字。
